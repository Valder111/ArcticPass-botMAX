# ArcticPassBot

Чат-бот мессенджера MAX для просмотра домов Норильска и коротких справок о городе и сервисе ArcticPass

Доступ к основному сценарию: живой бот в MAX Ссылка: [https://max.ru/t80_hakaton_max_bot](https://max.ru/t80_hakaton_max_bot) (локально внутри мессенджера MAX: @t80_hakaton_max_bot)

Локальный контейнер эту ссылку не заменяет Сценарий проходят в клиенте MAX Контейнер нужен, чтобы поднять того же бота из исходников.

## Назначение

Бот отвечает в чате: меню, справка о Норильске, описание ArcticPass, поиск дома по улице или QR, карточка дома со ссылкой на паспорт

## Основной сценарий

1. Пользователь открывает бота и нажимает «Старт» или пишет `/start`
2. Бот присылает приветствие и меню
3. «О Норильске» и «Как работает» листают тексты кнопками «Далее» и «Назад»
4. «Найти дом по улице» просит адрес. Пользователь пишет улицу или улицу с номером
5. Бот присылает карточку, QR и ссылку «Открыть паспорт»



## Состав и архитектура

Локальный компонент один: процесс бота на Go (`bot/`)

Бот забирает обновления long polling у API MAX и отвечает туда же. Карточки домов читает по HTTPS из API ArcticPass. Своей базы и входящего HTTP-порта нет. Тексты меню и справок лежат в коде

Мини-приложение в локальный запуск не входит. Бот открывает его кнопкой и ссылкой

## Запуск

Из корня репозитория, когда `.env` заполнен по `.env.example`:

```bash
docker compose up --build -d
```

Команда собирает образ и запускает бота. Других локальных сервисов нет.

В логах должна появиться строка `Бот запущен и ожидает сообщений...`

```bash
docker compose logs -f bot
```

## Внешние сервисы

В этот Docker они не входят. Для проверки должны быть доступны снаружи.

**MAX**: Приём сообщений и отправка ответов. Нужен действующий `MAX_TOKEN` и бот, которого жюри открывает в клиенте MAX. Контейнер только ходит в API наружу

**API ArcticPass.** Данные домов. Адрес в разделе про окружение. Бот ходит без авторизации:

- `GET /api/max/v1/objects`
- `GET /api/max/v1/objects/{id}`
- `GET /api/max/v1/objects/{id}/apartment`
- `GET /api/v1/objects/{id}/qr` (PNG)

Сервер и база раздаются отдельно. Пока API отвечает по `BASE_URL`, локально их поднимать не нужно.

**Мини-приложение** `https://miniapp.xn--80aaxhbzfbdhihi.xn--p1ai` Ссылка из карточки: `/objects/{id}`. Кнопка «Открыть приложение» есть, если известны username и id бота. Проверка: живой бот и этот адрес В `compose.yaml` мини-приложения нет: клиент MAX открывает публичный HTTPS из кабинета бота, а не контейнер на localhost.

## Работа с данными

Бот ничего не записывает. На время процесса держит в памяти индекс QR (код на id объекта). Индекс собирается постранично из списка объектов и пропадает после остановки.

Поиск. Строка с улицей и номером дома: номер сравнивается с `house_number` . Строка без номера: поиск по тексту Несколько домов: бот просит номер и показывает до 6 адресов Один дом: карточка (название, адрес, район, этажи, год, число квартир, стены, УК) и QR, если API отдал PNG

QR в чат: UUID из 36 символов либо текст `arcticpass:object:{id}`

## Тестовые данные

Отдельной загрузки нет. Дома уже лежат в API.

Сообщения для проверки:

- `Бегичева` Несколько домов, бот просит номер
- `Бегичева 45` Одна карточка, если дом есть в API
- `Неттакойулицы 1` Ответ «Дом не найден»
- UUID из поля QR объекта в API Карточка этого дома



## Пошаговая проверка

1. Скопировать `.env.example` в `.env` Вписать `MAX_TOKEN` и `BASE_URL`
2. Выполнить `docker compose up --build -d`
3. Убедиться в логах, что бот ждёт сообщения
4. Открыть бота в MAX Отправить `/start`
5. Проверить приветствие и кнопки меню
6. «О Норильске»: текст, «Далее», «Назад», «В меню»
7. «Как работает»: такой же листаемый текст
8. «Найти дом по улице», затем `Бегичева 45`
9. Карточка, изображение QR, ссылка «Открыть паспорт»
10. `docker compose down` - бот перестаёт отвечать. `docker compose up -d` поднимает его снова

## Ограничения

Один токен и один процесс long polling. Второй экземпляр с тем же токеном забирает обновления себе.

Без доступа к MAX или к API карточка дома не строится. Справки «О Норильске» и «Как работает» от API не зависят.

Памяти диалога нет. Каждое сообщение обрабатывается сразу. После перезапуска незавершённый ввод не сохраняется.

Кнопка «Открыть приложение» не появляется, пока нет username и id бота.

Мини-приложение, сервер и база в этот `compose.yaml` не входят.

## Остановка и повторный запуск

Остановка:

```bash
docker compose down
```

Повторный запуск без пересборки:

```bash
docker compose up -d
```

Запуск после изменений в коде:

```bash
docker compose up --build -d
```

Перезапуск уже собранного контейнера:

```bash
docker compose restart bot
```
